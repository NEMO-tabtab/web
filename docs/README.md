## 원칙 → 규칙 → 확인 방법

**굵은 글씨**는 필수 규칙입니다. "자동(예정)"은 후속 이슈로 도구에 맡길 것입니다.

| 원칙 | 규칙 | 확인 방법 |
|---|---|---|
| P1 기록은 사라지지 않는다 | **R1** 저장 구조는 새 버전으로만 | 리뷰 1명 + 테스트 |
| | **R2** 삭제는 표시만 | 리뷰 1명 + 테스트 |
| | **K1** 저장소는 정해진 입구로만 | 리뷰 → 자동(예정: 린트) |
| | **K3** 저장소를 고치면 테스트도 | 리뷰 → 자동(예정: CI) |
| | K5 실패를 삼키지 않는다 | 리뷰 → 자동(예정: 린트) |
| P2 개인정보는 안전한 길로만 | **R3** HTTPS와 본인 요청으로만 | 리뷰 1명 |
| | **R4** 개인정보를 로그에 남기지 않는다 | 리뷰 |
| | **R5** 비밀값은 저장소·브라우저에 두지 않는다 | 자동(`.gitignore`) + 리뷰 |
| | **K2** 화면은 서버를 직접 부르지 않는다 | 리뷰 → 자동(예정: 린트) |
| P3 `main`은 운영이다 | **C1** `main`에는 PR로만 | 자동(예정: 브랜치 보호) |
| | **C2** 위험 영역 PR은 승인 1명 | 리뷰 → 자동(예정: `CODEOWNERS`) |
| | **PR2** 빌드가 성공한 PR만 머지 | 자동(Vercel) |
| | **PR3** 확인한 것과 되돌리는 방법을 적는다 | 리뷰 |
| P4 기기가 먼저, 서버는 아껴서 | **R6** 기기에 먼저 저장, 서버에는 바뀐 것만 | 리뷰 1명 |
| P5 공통 부품과 토큰으로만 | U1 토큰만 / U2 색은 두 곳 함께 / U3 글자 크기 단계 | 리뷰 |
| | U4 공통 부품 먼저 / U5 세 가지 상태 / U6 이름표와 포커스 / U7 문구 | 리뷰 |
| | K4 실패는 화면 안에서 | 리뷰 → 자동(예정: 린트) |
| P6 도구가 지키게, 작게 | C3 브랜치 이름 / K6 파일 이름 / K7 이유 주석 | 자율 |
| | C4 제목 형식 | 리뷰 → 자동(예정: PR 제목 검사) |
| | PR1 PR 하나에 기능 하나 / PR4 스쿼시 머지 | 리뷰·자율 |
| | **I4** 작업은 이슈에서 시작, 만들기 전에 중복 정리 | 리뷰·자율 |
| | **I3** 모두 해결된 이슈는 PR이 닫는다 | 리뷰·자율 |
| | I1 이슈 크기 / I2 완료 조건 | 자율 |
