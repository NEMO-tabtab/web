# 0004. 굿즈샵 지도: 바깥은 네이버 지도, 안은 직접 만든 격자 데이터 + SVG 입체 그림

날짜: 2026-11-20 / 상태: 방향 확정, 구현 전 (묶음 이슈 #106)
고침: 2026-11-23 내부 지도의 격자 한 칸을 50cm에서 25cm로 (#188)
고침: 2026-11-26 내부 지도를 더 만드는 일을 미룸 (#240) — 까닭과 지금까지 한 것, 다음에 정할 것은 [0009](0009-indoor-map-on-hold.md)

## 결정

- **바깥 지도**(굿즈샵이 어디 있는지)는 네이버 지도(네이버 클라우드 플랫폼 Maps, Web Dynamic Map)를 쓴다.
- **내부 지도**(매장 안 어디에 어떤 가챠 기기가 있는지)는 지도 서비스를 쓰지 않고, 직접 만든 데이터를 SVG로 그린다. 위에서 비스듬히 내려다본 입체(등각 투영)로 보여 준다.
- 서버 없이 시작한다. 데이터는 저장소의 정적 JSON이고, 오프라인에서도 내부 지도가 열린다.

## 내부 지도 데이터의 원칙

구현할 때 아래에서 벗어나면 이 문서를 고치는 PR을 먼저 올린다.

- **저장하는 것은 위에서 내려다본 2D 격자뿐이다.** 1칸은 25cm — 가챠 기계 한 대의 폭이 한 칸이다(처음에는 50cm였다. 아래 "격자 한 칸을 25cm로 바꾼 까닭"). 구조 파일이 `cellCm`으로 자기 칸 크기를 적는다. 입체는 화면에서 계산한다. 3D 파일은 저장하지 않는다.
- **바뀌는 주기별로 나눈다.** 기기는 시리즈를 복사하지 않고 `seriesId`로 가리킨다.

  | 묶음 | 담는 것 | 바뀌는 때 |
  |---|---|---|
  | 굿즈샵 | 이름, 좌표, 주소, 층 | 거의 안 바뀜 |
  | 매장 구조 | 벽, 진열대, 기기 자리 | 매장을 고칠 때 |
  | 기기 내용 | 자리마다 어떤 시리즈가 들어 있는지, 마지막으로 확인한 날 | 자주 |
  | 시리즈 | 이름, 가격, 이미지 | 새 시리즈가 나올 때 |

- **버전을 둘로 나눈다.** 매장 구조에는 `version`(내용이 바뀌면 올림)과 `schemaVersion`(형식이 바뀌면 올림)을 따로 둔다. 구조 파일의 경로에 버전을 넣어(`layouts/{shopId}/v{version}.json`) 한 번 낸 파일의 내용은 바꾸지 않고, 무엇이 최신인지는 굿즈샵 목록이 가리킨다.
- **검사는 스키마 하나로 한다(zod).** 격자 밖 좌표, 겹치는 물체, 구조에 없는 자리를 가리키는 기기를 걸러낸다. 앱이 불러올 때와, 나중의 편집기·서버 발행이 같은 스키마를 쓴다.
- **손그림 선은 이미 있는 `#rough-line` 필터로 낸다.** 그리기 라이브러리(rough.js 등)를 더하지 않는다.

## 이유

- 네이버 지도는 Style Editor로 지도 색을 바꿀 수 있다. 흑백 손그림 디자인에 맞출 수 있고, 카카오에서 필요했던 CSS 흑백 필터와 그 약관 확인이 필요 없다.
- 매장 안의 기기 배치는 어떤 지도 서비스나 공공데이터에도 없다. 어차피 직접 입력해야 하므로 형식을 우리가 정한다.
- 2D 격자는 사람이 JSON으로 직접 쓸 수 있을 만큼 단순하고, 검사하기 쉽고, 그리는 방식을 바꿔도 데이터가 그대로다.
- SVG는 번들에 더할 것이 없고, 기기 하나하나가 요소라 누르기·접근성 라벨을 붙이기 쉽다.

## 격자 한 칸을 25cm로 바꾼 까닭 (2026-11-23, #188)

**문제.** 50cm 칸으로는 가챠 기계를 제 크기로 적을 수 없었다. 가상 굿즈샵(`nemo-virtual` v1)은 위로 쌓인 기기 한 줄을 폭 1m(2칸)로 적었고 벽도 한 칸(50cm) 두께였다. 내부 지도를 봐도 실제 가챠샵이 떠오르지 않았다.

**확인한 실제 치수** (2단 기계, 2026-11-23 확인)

| 기계 | 폭 × 깊이 × 높이 | 출처 |
|---|---|---|
| 반다이 캡슐 스테이션 | 280 × 450 × 1300mm, 약 19kg | [중고 판매 제원](https://gacha-gacha.net/hon/cps/30803), [대여 제원](https://www.rentalpronto.net/%E5%85%A8%E5%95%86%E5%93%81/%E3%82%A4%E3%83%99%E3%83%B3%E3%83%88%E7%94%A8%E5%93%81/%E3%82%AC%E3%83%81%E3%83%A3%E3%82%AC%E3%83%81%E3%83%A3/) |
| 타카라토미아츠 Gacha.2 Ez | 290 × 450 × 1275mm, 약 20kg | [제원 정리](https://gachahon.com/g-2ez/), [중고 판매 제원](https://gacha-gacha.net/hon/usd/30775) |

**정한 것.** 1칸을 25cm로 하고 표준 기계를 이렇게 적는다.

- 바닥: 폭 1칸 × 깊이 2칸 (25 × 50cm). 손잡이가 남·북을 보면 `w` 1, `d` 2 / 동·서를 보면 `w` 2, `d` 1
- 높이: 2단 5칸(125cm), 3단 8칸(200cm)
- 실제와의 차이는 폭 -11~14%, 깊이 +11%, 2단 높이 -2~4%다. 벽 두께와 통로도 25cm 단위로 적는다.
- 기기 종류별 크기(1단 대형, 4단 등)는 기계 카탈로그(#163)에서 정한다.

**지키는 것.** 한 번 낸 구조 파일은 고치지 않는다. 50cm로 낸 `nemo-virtual` v1은 그대로 두고, 스키마는 `cellCm` 25와 50을 모두 받는다. 그림은 칸 크기가 달라도 실제 크기가 같으면 같은 크기로 그린다. 새 구조는 25cm로만 쓴다.

**버린 대안**

- 50cm 칸을 그대로 두고 기기를 1칸으로 적기: 폭이 실제의 1.7~1.8배가 되고, 한 벽에 들어가는 기기 수가 실제의 절반 남짓이 된다.
- 50cm 칸 한 자리에 기기를 여러 줄 넣기(자리에 줄 수를 더함): 기기를 가리키는 방법(자리 + 단)이 바뀌어 물건의 "뽑은 곳" 기록과 백업 형식까지 고쳐야 한다.
- 10cm 이하의 촘촘한 칸: 실제 치수에 더 가깝지만 숫자가 커져 사람이 JSON으로 쓰기 어렵다. 손그림 지도에서 3cm 차이는 보이지 않는다.

**치르는 값**

- 좌표가 두 배 촘촘해져 구조 파일이 길어진다. 손으로 쓰기 버거워지면 편집기(#164)를 앞당긴다.
- 기기 하나가 화면에서 몇 px로 작아진다. 매장 전체를 보는 화면에서는 기기를 바로 고르기 어렵고, 크게 본 뒤에 고르게 된다.

**참고한 실제 매장의 밀도.** 도쿄의 캡슐토이 전문점 7곳이 ㎡당 4.4~6.2대다(예: 1,050대/218㎡, 766대/124.72㎡ — [FUN! JAPAN의 매장 정리](https://www.fun-japan.jp/ko/articles/13963)). 가상 굿즈샵 v1은 ㎡당 0.75대였다. 구조를 지어낼 때 이 범위를 따른다.

## 공공데이터를 쓰는 곳

- 굿즈샵 후보 목록: 소상공인 상가(상권)정보에서 업종 코드와 상호 키워드로 뽑고 사람이 검수한다. 좌표가 들어 있어 먼저 쓴다.
- 건물과 층: 도로명주소 API로 건물관리번호와 층을 붙인다.
- 쇼핑몰 단위로 묶기: 대규모점포 데이터(좌표계가 EPSG:5174라 변환이 필요하다).
- 매장 내부와 기기: 공공데이터가 없다. 현장 스케치로 직접 입력한다.

## 버린 대안

- 카카오맵: 타일 색을 바꿀 수 없다. 결제 수단 없이 시작할 수 있는 점은 낫다.
- 브이월드·구글 지도: 스타일 변경과 국내 장소 데이터, 비용에서 네이버보다 나은 점을 찾지 못했다.
- 3D 라이브러리(three.js 등)로 내부 그리기: 번들이 크고, 손그림 느낌과 접근성 라벨을 내기 어렵다. 필요한 것은 고정된 네 방향의 입체 그림이지 자유로운 시점이 아니다.
- 굿즈샵 하나에 JSON 한 개, 미터 단위 윤곽(#109의 처음 안): 기기 내용만 바뀌어도 구조 전체를 다시 내야 하고, 겹침 검사가 어렵다.

## 확인이 남은 것

- 네이버 지도의 현재 무료 이용량과 초과 요금(공식 요금표로 확인하지 못했다. 2차 자료로는 Dynamic Map 월 600만 건)
- Style Editor 스타일의 추가 요금. 적용 방법은 확인했다(2026-11-21): 콘솔의 Style Editor에서 스타일을 만들어 발행하고, GL 서브모듈(`submodules=gl`)을 받아 `gl: true`, `customStyleId`로 건다. 커스텀 스타일을 쓰면 위성·지형 같은 기본 지도 유형과 교통·자전거 레이어는 쓸 수 없다. 앱은 `NEXT_PUBLIC_NAVER_MAP_STYLE_ID`가 있을 때만 건다
- 콘솔에 등록하는 Web 서비스 URL 형식(운영 도메인, 로컬 주소). Vercel 미리보기 주소에서는 지도가 뜨지 않을 것으로 본다
- 상가정보에서 가챠샵에 해당하는 업종 코드
- 시리즈 이미지를 실을 수 있는지(제조사 이미지의 이용 허락), 사용자가 제보한 사진의 약관

## 챙길 것 (네이버 지도)

- 반드시 **Maps** 상품으로 신청한다. 예전 AI NAVER API 쪽 지도 API는 2025-07-01부터 무료 이용량이 없다.
- 무료 이용량은 대표 계정 1개에만 적용된다. 결제 수단이 걸리므로 콘솔에서 사용량 알림을 설정한다.
- 스크립트는 `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=…`로 불러온다.
- 지도 호출은 `src/lib/map/` 한 곳에 모은다. 지도 서비스를 바꾸는 비용을 작게 유지하기 위해서다.

## 나중으로 미룬 것

- 내부 지도를 더 만드는 일 전체(2026-11-26, [0009](0009-indoor-map-on-hold.md)): 기계 종류 카탈로그(#163), 편집기(#164), 실제 매장의 내부 지도(#109). 이미 만든 화면·코드·데이터와 위의 원칙은 그대로 둔다.
- 관리자용 격자 편집기: 매장 2~3곳을 JSON으로 직접 써 본 뒤에 만든다.
- 서버 쪽 저장과 발행(초안 → 발행 → 되돌리기), 앱이 바뀐 것만 받는 방식.
- 현재 위치 표시, 재고처럼 자주 바뀌는 정보.

## 다시 볼 때

- 결제 수단 등록이 팀 사정상 어렵거나, 확인한 무료 이용량이 예상보다 작으면 카카오맵을 다시 본다.
- 매장이 10곳을 넘거나 기기 내용을 여러 사람이 고치게 되면 정적 JSON을 서버 저장으로 옮긴다.
- 격자(25cm)로 표현하지 못하는 매장(비스듬한 벽, 둥근 진열대)이 나오면 형식을 다시 본다.
