# 0005. 가챠 카탈로그, 빠른 등록, 사진으로 가챠 찾기

날짜: 2026-11-23 / 상태: 방향 확정, 구현 중 (묶음 이슈 #165)

## 결정

- **앱의 중심은 "얼마나 모았나"(도감)다.** 금액(자산)보다 시리즈별로 몇 종을 모았는지를 먼저 보여 준다(#170).
- **등록은 매장에서 뽑은 직후를 기준으로 한다.** "시리즈 고르기 → 나온 종류 탭 → 한 번에 등록"으로, 같은 시리즈를 여러 번 뽑아도 한 번에 끝낸다(#168). 카탈로그에 없는 굿즈는 지금의 상세 등록 화면을 쓴다.
- **카탈로그(작품·시리즈·종류)는 팀이 손으로 입력하는 정적 JSON으로 시작한다.** `public/shops/titles.json`, `public/shops/series.json`. 입력 방법은 [`docs/catalog.md`](../catalog.md), 형식은 `src/lib/shops/schema.ts`(#166). 나중에 서버로 옮긴다(#97의 3-5).
- **데이터는 세 단계로 쌓는다.** 1차: 공개 자료를 보고 손으로 입력한다. 2차: 가챠 회사가 만든 자료를 쓴다. 3차: 실제 사용자 사진을 쓴다.
- **사진으로 가챠 찾기**: 기기 대지를 찍으면 1-1) 글자 인식 또는 1-2) 이미지 비교로 시리즈를 찾는다. 결과는 세 가지로 나눈다: 확정 / 후보 2~3개 / 못 찾음(직접 찾기로 넘어감). 1차는 글자 인식만 실험한다(#171). 이미지 비교는 기준 이미지를 쓸 수 있는 2차부터 한다.
- **확률**: 회사가 밝힌 값은 그대로 쓴다. 밝히지 않은 종류끼리는 남은 확률을 똑같이 나눈다. 아무것도 밝히지 않았으면 1/n이다. 계산한 값은 화면에 "추정"으로 표시한다(`variantOdds`).
- **한국 가격**: 가게마다 달라서 여러 가게에서 본 1회 가격의 평균과 평균 낸 가게 수를 저장한다. 공식 일본 가격(엔)은 따로 적고 원으로 바꿔 섞지 않는다.
- **현재 장소**: 근처 굿즈샵만 자동으로 기록하고, 층·기기·단은 사용자가 고른다(#169).
  - 위치는 기기 안에서 가장 가까운 굿즈샵을 고르는 데만 쓴다. 좌표는 저장하지 않고 서버로 보내지 않는다.
  - 사진 인식에서는 앱 카메라로 그 자리에서 찍은 경우에만 위치를 쓴다.

## 지킬 것

구현할 때 아래에서 벗어나면 이 문서를 고치는 PR을 먼저 올린다.

- **공식 사이트를 자동으로 수집하지 않는다.** 반다이 가샤폰 사이트의 이용 조건은 사전 허락 없는 자동 수집과 AI 2차 이용을 금지한다(https://gashapon.jp/news/info_260603/). 페이지를 보고 사실(이름, 종류 수, 가격, 종류 이름)만 손으로 적는다.
- **이용 권리를 확인하지 않은 이미지는 저장소에도 앱에도 넣지 않는다.** 이 저장소는 공개 저장소다.
- **카탈로그 id는 바꾸지 않는다.** 사용자 기록이 id를 가리킨다. 기록에는 고른 순간의 시리즈·종류 이름을 함께 적어, 카탈로그가 바뀌어도 읽히게 한다('뽑은 곳'과 같은 방식, #167).
- **선택 칸을 더할 때는 `SHOP_SCHEMA_VERSION`을 올리지 않는다.** 예전 앱은 모르는 칸을 버리고 읽는다. 올리면 새 데이터를 받은 예전 앱이 형식 오류로 멈춘다.
- **사진은 서버에 저장하지 않는다.** 3차의 사진 기여는 사용자가 동의한 경우에만 따로 받는다(#97의 3-7).

## 이유

- 매장에서 가챠를 여러 번 뽑으면 시리즈·가격·매장이 같은데도 등록을 처음부터 반복해야 했다.
- 캡슐 가챠는 바코드가 없는 경우가 많다. 블라인드 박스는 바코드가 있어도 같은 시리즈면 대개 같아서, 어떤 종류가 나왔는지는 사람이 골라야 한다.
- 2026-11-23 조사 기준으로, 반다이·타카라토미아츠·키탄클럽은 상세 페이지에 종류 수·가격·발매 시기를 싣지만 종류별 확률은 싣지 않았다(각 상세 페이지 1개씩 확인). 공식 확률이 없으면 무엇인가로 보여 줘야 하는데, 1/n이 가장 단순하고 데이터를 고치기도 쉽다. 대신 추정임을 숨기지 않는다.
- 한국 가격을 공개하는 공식 출처는 찾지 못했다. 공식 가격은 엔화뿐이다.

## 버린 대안

- **공식 사이트 자동 수집:** 이용 조건 위반이다.
- **1/n을 확정값처럼 표시:** 시크릿처럼 드문 종류가 있으면 틀린 숫자가 된다. 그래서 추정 표시를 붙인다.
- **갤러리 사진의 위치 정보(EXIF) 쓰기:** Android는 위치 정보를 지워서 주는 경우가 많고, 찍은 곳이 지금 있는 곳과 다를 수 있다.
- **결과를 확정 / 못 찾음 두 가지로만 나누기:** 애매한 경우를 모두 버리게 된다. 후보 2~3개를 고르게 하는 편이 손해가 작다.

## 아직 정하지 않은 것

- 글자 인식을 기기 안에서 할지 서버에서 할지: #171 실험 결과로 정한다. 서버라면 #97의 3-6 API가 필요하다.
- 위치정보법상 신고·위치 약관이 필요한지, 개인정보처리방침에 무엇을 적을지: #169
- 사진 인식의 비용과 호출 제한(로그인 사용자만, 기기당 횟수 등)
- 2차 회사 자료를 요청하는 방법과 이미지 이용 허락
- 카탈로그를 서버로 옮기는 시기. 시리즈가 수백 개가 되거나 여러 사람이 동시에 고치게 되면 옮긴다.

## 다시 볼 때

- 회사가 확률을 공개하거나 3차 사용자 기록이 충분히 쌓이면, 확률을 보여 주는 방식을 다시 본다.
- 글자 인식 실험(#171)의 정확도가 낮으면 이미지 비교를 앞당길지 다시 본다.
