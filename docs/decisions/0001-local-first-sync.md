# 0001. 기기 우선 저장, 로그인 사용자만 서버 동기화

날짜: 2026-11-15 / 상태: 방향 확정, 동기화는 구현 전

## 결정

- 앱은 기기 저장소(IndexedDB, Dexie)를 기준으로 동작한다. 로그인하지 않아도 모든 핵심 기능을 쓴다.
- 로그인한 사용자의 데이터는 서버에도 저장한다. 이때 서버 사용을 아낀다.

## 서버를 아껴 쓰는 방향

구현할 때 아래에서 벗어나면 이 문서를 고치는 PR을 먼저 올린다.

- 화면은 늘 기기에서 읽는다. 화면을 열 때마다 서버에서 목록을 받아 오지 않는다.
- 바뀐 것만 보낸다: 마지막 동기화 시각 이후 `updatedAt`이 바뀐 기록만. 삭제는 `deletedAt`으로 알린다.
- 묶어서 보낸다: 기록마다 요청하지 않고 한 번에 여러 건.
- 때를 정해 보낸다: 앱을 열 때, 저장하고 잠시 뒤, 다시 온라인이 됐을 때. 일정 간격으로 계속 부르지 않는다.
- 사진은 줄인 파일만, 한 장당 한 번만 올린다(`src/lib/image.ts`).

## 이미 준비된 것 (PR #94)

`src/lib/db/index.ts`의 `Product`는 기기에서 만든 UUID를 `id`로 쓰고 `updatedAt`, `deletedAt`, `serverId`, `ownerId` 자리를 갖고 있다.

## 버린 대안

- 서버 우선(이전 `main`의 방식): 오프라인에서 못 쓰고, 화면마다 요청이 나간다.
- 기기 전용: 기기를 잃으면 기록도 잃는다.

## 아직 정하지 않은 것

- 두 기기에서 같은 기록을 고쳤을 때 어느 쪽을 남길지
- 로그인 전 기록을 로그인 뒤 계정에 합치는 방법
- 백엔드 API의 모양
