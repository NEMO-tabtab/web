# 가챠샵 목록 채우기

지도에 싣는 가챠샵·뽑기 가게(`public/shops/index.json`)를 공공데이터에서 뽑아 사람이 검수한 뒤 넣는 방법입니다.
방향은 [결정 기록 0004](../../docs/decisions/0004-map-and-indoor-map.md)의 "공공데이터를 쓰는 곳"을 따릅니다.

## 순서

1. **자료 받기** — 공공데이터포털의 [소상공인시장진흥공단_상가(상권)정보](https://www.data.go.kr/data/15083033/fileData.do)에서 파일을 내려받아 압축을 풉니다. 로그인·인증키 없이 받을 수 있고, 이용허락범위는 "제한 없음"입니다(2026-11-23 확인). 분기마다 새로 나옵니다. 시도별 CSV이며 저장소에는 넣지 않습니다(전체 약 1.5GB).
2. **후보 뽑기**

   ```bash
   node scripts/shops/find-candidates.mjs find <받은 폴더>/소상공인시장진흥공단_상가(상권)정보_서울_202609.csv
   ```

   아래 "후보를 고르는 규칙"에 맞는 곳을 `scripts/shops/candidates.json`에 합칩니다. 이미 있는 후보는 건드리지 않습니다.
3. **검수** — 지도 앱과 SNS로 확인하고, `candidates.json`에서 후보마다 `review`를 고칩니다.

   | 값 | 뜻 |
   |---|---|
   | `todo` | 아직 안 봄 |
   | `ok` | 영업 중이고 뽑기 기기가 있다. 지도에 싣는다 |
   | `no` | 싣지 않는다. `note`에 까닭을 적는다(폐업, 뽑기 기기 없음, 다른 후보와 같은 곳) |

   이름·주소·층(`floorNote`)이 실제와 다르면 이 파일에서 고칩니다. `kind`·`matched`·`category`·`building`은 검수할 때 참고하라고 둔 값이고 지도에는 쓰지 않습니다.
4. **싣기**

   ```bash
   node scripts/shops/find-candidates.mjs apply
   pnpm test
   ```

   `ok`인 후보에 굿즈샵 `id`를 매겨 `public/shops/index.json`에 더하고, 매긴 `id`를 `candidates.json`에도 적습니다. 이미 목록에 있는 굿즈샵은 건드리지 않습니다.

## 후보를 고르는 규칙

업종 대분류가 소매 또는 예술·스포츠인 곳 가운데 아래에 해당하는 곳입니다(`candidates.mjs`).

| `kind` | 고르는 기준 |
|---|---|
| `gacha` | 상호에 가챠·갓챠·가차·가샤폰·캡슐토이·gacha·gashapon. "엄마가차린밥상" 같은 상호는 뺀다 |
| `claw` | 상호에 "뽑"(뽑기방, 인형뽑기, 뽑아핑…). 캐치·캐칭·크레인은 오락·장난감·문구·종합 소매 업종일 때만 |
| `franchise` | 상호에 위 낱말이 없는 뽑기 프랜차이즈의 지점. 이름 목록은 `candidates.mjs`의 `FRANCHISES`. 오락·장난감 업종일 때만 |

- 프랜차이즈 목록은 상가정보에서 지점이 10곳 넘게 되풀이되는 이름을 고른 것입니다. 뽑아핑·캐칭덕·크레이지팡은 뽑기 프랜차이즈임을 확인했고(상호에 "뽑"·"캐칭"이 있어 `claw`로 잡히기도 합니다), 봉봉스테이션·블링팝·모모스테이션·헌터독·뽀끼뽀끼·버블팝·유에프오·팡야팡야·미니돌은 확인하지 못했습니다. 검수에서 뽑기 가게가 아니면 목록에서 뺍니다.
- 규칙에 걸리지 않는 곳(대형 쇼핑몰 안의 가챠 코너 등)은 `candidates.json`에 손으로 더합니다. `sourceId`는 빼고, `region`에 시군구코드 5자리를 적습니다.

## 굿즈샵 id

`kr-(시도코드 2자리)-(시군구코드 3자리)-(그 시군구에서 몇 번째)` — 예: `kr-11-440-001`은 서울특별시(11) 마포구(440)의 첫 번째입니다.

- 지역코드는 상가정보의 시군구코드(행정표준코드 5자리)를 둘로 나눈 것입니다. 동까지는 넣지 않습니다(동은 이름과 경계가 자주 바뀝니다).
- 번호는 지도에 실을 때(`apply`) 매깁니다. 검수에서 뺀 후보는 번호를 쓰지 않습니다.
- 한 번에 여럿을 실으면 상가업소번호 순(대체로 등록된 순)으로 매기고, 손으로 더한 후보는 그 뒤에 이름 순으로 매깁니다.
- 한 번 매긴 `id`는 바꾸지 않고, 지도에서 내린 굿즈샵의 번호도 다시 쓰지 않습니다. 사용자의 기록이 `id`로 굿즈샵을 가리키기 때문입니다. 행정구역이 바뀌어도 이미 매긴 `id`는 그대로 둡니다.
- 번호는 세 자리로 시작하고 999를 넘으면 네 자리가 됩니다.

## 알아 둘 것

- 후보는 상호만 보고 고른 것입니다. 폐업한 곳, 이름만 비슷한 곳이 섞여 있으므로 검수하지 않은 후보는 지도에 싣지 않습니다.
- 같은 곳인지는 상가업소번호(`sourceId`)로 알아봅니다. 다시 뽑아도 검수 결과와 `id`가 유지됩니다.
- 새 자료에 없는 기존 후보는 "이번 자료에 없음"으로 알려 줍니다. 폐업했는지 확인해 `no`로 바꾸고, 지도에서 내릴지는 따로 정합니다.
